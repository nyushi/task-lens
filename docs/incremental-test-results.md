# 合成入力の検証

以下の数値はコミット`b0b6901`時点の記録です（その後の更新時刻フィールド等で入力量は変わります）。
`go test -race -v ./...`の`TestLargeInputBudgetMeasurement`で再現できます。
時計と変換器をテスト内で置き換え、実モデルは呼びません。15担当×10,000字の合成日本語、合計150,000字（本文450,000 UTF-8 bytes）を使用します。

| ケース | 外部変換呼出数 | 入力bytes | 出力bytes |
|---|---:|---:|---:|
| 初回、既定設定 | 0 | 0 | 0 |
| 明示的に末尾1,000字から開始、15担当 | 15 | 55,200 | 3,000 |
| 変化なし | 0 | 0 | 0 |
| 1担当に100字追加 | 1 | 1,366 | 200 |
| 同担当で20回・200秒の連続変更、静止後 | 1 | 1,126 | 200 |
| 再接続後10,120字の画面を再同期 | 0（上限で保留） | 0 | 0 |

明示的bootstrapテストでは`bootstrap_tail_chars=1000`と`max_total_output_bytes=256000`を指定しています。
既定の出力予約予算は64,000bytesなので、初回文字数制限を緩和しても最大8呼出で止まります。
これらは短い合成プロンプトと200bytesのダミー出力での実測です。実際のプロンプト、Task、ラッパーで値は変わります。
実token数・請求額・要約品質を測定した結果ではありません。

追加検証：

- 同一画面の上書き・削除・スクロール相当の置換、Unicode境界。
- revisionや取得時刻だけの変化では呼び出さない。
- 連続変化でも最大待機を超えると予算内で試行。
- 変換中に対象が変化したら破棄、別担当の変化では破棄しない。
- 失敗を含む累計呼出予算、再試行間隔、大きすぎるプロンプトの送信前保留。
- 再接続後の小さい画面で復旧、消えた担当はstaleで保持。
- 過去の根拠本文を前回状態から除去、他担当のID・参照を拒否。
- ダミー外部プロセスを実際に起動し、version 2 JSONを検証してTaskストアへ反映。
- 既存core/TUI模擬ソケットと汎用Task/Webの回帰テスト。

実Herdr TUIへの接続・実ログの欠落率・実モデルの品質と請求は未検証です。
